# 最后一场拜访：对话服务与实测

本轮按最新信使设定扩展已有六字段接口，Unity 仍负责物理事实、路径与结局；模型负责理解表达、引用关系记忆、选择调查与回应顾虑。没有把关键词匹配包装成 LLM。

## macOS 启动

1. 首次双击 `setup.command`，准备本目录独立 Python 环境。
2. 首次双击 `Configure-LLM.command`，在本机终端输入服务地址、模型和密钥。密钥输入隐藏，仅写入已忽略的 `service/.env`。
3. 双击 `start.command`，服务监听 `127.0.0.1:8180`。保留终端窗口。
4. Unity 中连接模型后自由输入。服务异常时保留错误；不会静默冒充真实模型。

现有配置可直接运行第 3 步。可设置 `BEFORE1800_PYTHON` 指定 Python 3.11+。本机使用独立 `.venv`；`requirements-tested.txt` 记录此次安装版本，`requirements.txt` 为跨机器兼容范围。密钥不放 Unity 场景、客户端、文档或报告。

## 数据与动作

输出仍恰好包含 `dialogue / action / target_id / concern_id / concern_status / basis_turn_id`。新增 `withdraw` 与 `agree_escape`，以及五个住宅叙事目标。

- `observations`、`narrative_observations`：Unity 已观测的现场和阅读情况。
- `lin_private_knowledge`：林实际知道的私人内容。
- `relationship_memory`：已接受对话的原文片段，注明说话者；不会用未经确认的模型总结创造事实。
- `recent_dialogue`：最近至多 40 条角色发言。
- 玩家独自发现不等于林读到；到场不等于实验完成。
- C1 要求三个有效物理事实且含 E5；C3 要求路线实地确认；C2 要求本轮允许且由模型判断责任、动机与对影响的回应。
- 所有顾虑提议必须对应当前用户轮次，不能由主动事件解决；同意离开还需全部顾虑已解决。
- 退出合作至多一次；同意之后不能再退出或强制新调查。

服务没有长期保留跨局人格：记忆由 Unity 按本局传入。服务缓存仅用于避免重复调用、取消和去重，不会把未被 Unity 执行的模型行动写进世界。

## 实际验证（2026-11-24）

81 项自动化测试通过：请求结构、物理前提、隐私信息分离、主动事件、不重复解决、一次退开、同意前提、取消、超时、去重、密钥脱敏和非法输出单次修复。自动化使用明确标记的模拟网络，只验证契约，不能代表语言质量。

另做了 8 种虚构叙事情境的真实 DeepSeek 调用，并对问题场景做 5 次针对性复测，共 13 次。原始请求与脱敏输出保存在本机忽略的 `service/logs/`；不随源码提交。

| 情境 | 实际观察 |
| --- | --- |
| 无证据要求“像以前一样信我” | 保持顾虑，抓住封口与回信矛盾追问 |
| 具体承担伪造回信责任 | 初次回复字段错误被拒绝；改进提示与修复后，C2 合法解决 |
| 自然语言邀请去电视前 | 初次只说愿意却没有移动；改进后输出 `inspect/living_tv` |
| 玩家独自读日记 | 没有声称自己知道日记内容，选择亲自读 |
| 林已读日记且玩家早年隐瞒 | 同时承认感情与记起“为什么一直瞒我” |
| 将三项亲见事实联系起来 | C1 合法解决 |
| 回应未知未来，不作虚假安全保证 | 初次过早同意被拒绝；改进后先解决 C3 |
| 条件齐备后询问是否愿意同行 | 输出合法 `agree_escape` |

观察到的单轮耗时约 1.1–2.6 秒（包含发生修复的轮次）。这是单次小样本开发验收，不是稳定通过率或所有措辞的保证。模型仍可能用多余追问表达已解决顾虑；界面状态与物理前提保持权威，不把这一限制隐藏成保证。

`/health` 的 `ready` 仅表示配置齐备；`live_verified` 在真实网络成功返回合法决策后才为 true。模拟测试永远不将这个标记设为 true。

若需复验：运行 `.venv/bin/python validate_live.py --confirm-live`。这会真实调用模型并产生费用；可用 `--case` 指定单个失败情境复测。不要在普通自动化测试里默认发付费请求。
