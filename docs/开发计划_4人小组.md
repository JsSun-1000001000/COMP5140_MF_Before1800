## 0. 执行原则（必须遵守）

1. **先闭环，后装饰**：优先跑通「玩家输入 → LLM 提议 → Unity 校验 → 场景执行 → 状态回写」。
2. **Unity 持有权威状态**：证据、时间、路线、顾虑、结局只能由程序写入，模型不可覆盖。
3. **最小可通关集**：首版必须保留 **E1 + E4 + E5**、**C1/C2/C3**、截止时钟、共同逃离；E2/E3 可延后。
4. **真实 LLM 演示**：提交视频禁止用假返回冒充模型；密钥不进仓库。
5. **每日可集成**：每人下班前合并到主分支一次，避免最后一天合并不了。

### 1.1 共享接口约定（第 1 天冻结）

```text
GameState {
  time_hms,                 // 17:00 → 18:00
  verified_evidence,        // {E1,E2,E4,E5}
  narrative_seen,           // {E3?}
  concerns: C1|C2|C3 → open|resolved
  cooperation_mode: talking|withdrawn|following
  route_confirmed: bool
  escape_agreed: bool
  active_experiment?        // E4 阶段等
}

LLM Output {
  dialogue, action, target_id?,
  concern_id?, concern_status?, basis_turn_id?
}

Actions: reply | follow | inspect | withdraw | agree_escape
```

证据写入规则（不可协商）：
- 仅 **到场 + 实验完成事件** 可写入 `verified_evidence`
- E3 只写 `narrative_seen`，永不计入通关门槛
- `agree_escape` 必须：≥3 条事实（含 E5）+ `route_confirmed` + C1–C3 全 resolved

## 9. 成功定义（小组对齐）

**成功** = 评委能在一次演示中看到：

1. 真实 LLM 驱动林的对话与动作；  
2. 至少完成 E1、E4、E5 的「发现 ≠ 验证」；  
3. C1–C3 被回应后共同在 18:00 前离开；  
4. 代码与报告一致，无密钥泄漏。

未完成 E2/E3、动画简陋、场景偏短 —— **可以提交**。  
没有真实 LLM、可用对话伪造证据、或无法共同逃离 —— **不算完成**。
