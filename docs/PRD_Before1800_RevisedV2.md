## 1. 概述

### 1.1 一句话概念

你扮演林最信任的朋友，实际上是参与制造他人生骗局的演员。你决定在导演 18:00 回岗前，带他发现并验证世界的漏洞，承认自己的隐瞒，帮助他自愿离开。

### 1.2 目标用户与体验价值

- **目标用户**：喜欢悬疑探索、叙事解谜和角色互动的玩家。
- **核心玩法**：玩家不仅寻找异常，还要选择验证方法、解释证据、回应林的担忧。
- **体验目标**（不预先宣称具有经过验证的教育或心理效果）：
  1. 凭什么相信某个世界是真实的？
  2. 被安排的生活中，感情是否仍有意义？
  3. 知道真相之后，谁有权决定是否离开？

### 1.3 核心矛盾

> **"我一直在骗你，现在你还能相信我吗？"**

事实验证与信任修复分别推进：林可以承认被监控，却仍害怕外界，或怀疑玩家再次欺骗他。**证据越充分，事实争论越少；情感顾虑仍需交流。**

## 2. 故事与世界观

### 2.1 故事设定与信息差

- 林把片场当作真实世界；玩家是扮演其朋友的演员，**开场便知道真相**。
- "上帝视角"指**信息优势**，不限定俯视镜头；首版采用**第一人称探索**。
- **休播日**：导演暂时离岗，但自动摄像、广告和广播设备仍运行；**18:00** 恢复控制并封闭出口，形成明确截止时间。
- 导演无需出场，也不制作追捕系统。

### 2.2 玩家已知与目标

- 玩家知道禁路通向片场外，但需要**确认当天路线可通行**，并找到**林能亲自验证的证据**。
- 林信任玩家的善意，却不会仅凭一句话否定全部人生。
- 玩家可以独自走到出口，但**帮助林共同离开才是任务目标**。

### 2.3 两个版本如何合并

| 保留的主线 | 吸收的机制 | 首版取舍 |
| --- | --- | --- |
| 演员朋友、18:00 截止、共同走出禁路 | 林主动查证、提出具体反驳、追问"你早就知道？"、临时退出对话 | 不加入七日循环、行动点和最终随机成功率 |
| 4 条可计数事实线索，另有 1 条可选叙事线索 | 把玩家的内部知识变成可以共同验证的预测 | 预测采用可启动的固定实验序列，不需要循环或日程记忆 |

## 3. 核心玩法与通关

### 3.1 玩法循环

| 阶段 | 玩家做什么 | 林与世界如何变化 |
| --- | --- | --- |
| 探索 | 检查住宅内的可疑物品，记录异常 | 物品进入"玩家已发现"，不自动写入林的知识 |
| 共同验证 | 邀请林跟随，并进行一个可观察的小实验 | 林到达目标并完成验证后，程序记录"林已验证" |
| 反问与主动行动 | 回应替代解释；也可能由林提出下一步调查 | 林可以请求查证、主动检查、追问隐瞒，或暂时保持距离 |
| 说服 | 承认参与骗局，解释证据与路线，回应具体担忧 | 林逐步接受真相与离开计划；事实可信不等于立即愿意走 |
| 共同逃离 | 带林进入禁路，穿过出口 | 两人都到达出口且时间早于 18:00，才算成功 |

### 3.2 通关条件（必须同时满足）

1. 在 **E1、E2、E4、E5** 中亲自验证**至少 3 条不同事实线索**，**必须包含 E5**；E3 不计数。
2. 路线已确认可通行（`route_confirmed`）。
3. 固定核心顾虑 **C1、C2、C3 均已解决**，`escape_agreed` 为 `true`。
4. 两人均在 **18:00 前**进入出口区域。

> 重复 ID 不累计，最终**不进行随机成功判定**。最小完整流程使用 E1、E4、E5。

### 3.3 时间与公平性

- 游戏内从 **17:00** 推进至 **18:00**。
- 探索、移动与设备实验运行时推进游戏时钟。
- **打开对话界面后**，组织表达、输入、阅读回复和 API 等待均**暂停时钟及场景动作**；开场、菜单、故障重试也暂停；关闭对话后恢复。
- 初步目标总体验约 **10–15 分钟**，但阅读与输入会延长时长，具体速率由试玩决定。
- 18:00 整不接受新通关；重新开始是重玩，不是故事内循环。

### 3.4 玩家自主选择范围

- 玩家选择调查顺序、验证方法与移动路线，并在 3 项固定顾虑内组织解释。
- 先做 E1、E4、E5 即可完整通关；E2 是可替换或补充的事实依据，E3 是可选情感内容，不增加门槛。
- 线索册区分**事实验证**与**叙事发现**。
- 暂停对话允许认真表达；时间压力来自探索与行动，而不是打字速度。

### 3.5 说服失败与恢复

- 林同意逃离前，施压可能触发**一次暂时退开**，每局最多一次。
- 玩家可用"恢复交流"按钮返回正常交流，再解释或提出验证；恢复**不自动解决顾虑**。
- 退开**不清除证据或已解决顾虑**。
- 同意逃离后，模型不能再次退开来阻断任务。
- 路径失败只暂停移动，可重新寻路，**不撤销同意**。

## 4. 事实线索系统

> 共 5 个线索点：**E1、E2、E4、E5 是可计数事实证据，E3 仅为叙事内容**。首个完整原型优先完成 E1、E4、E5，保留预测实验；E2 与 E3 随后加入。证据规则固定，不随模型台词改变。

### 4.1 线索总览

| 线索 | 现场验证方式 | 证明范围与用途 |
| --- | --- | --- |
| **E1 隐藏摄像头** | 林站在不同位置，观察镜头随之转动 | 证明秘密观察；仍可能被解释为安防，不能单独证明整个人生是节目 |
| **E2 广告屏后台信息** | 重现屏幕切换故障，显示与林当前动作关联的执行提示 | 普通广告轮播不是证据；后台信息揭示针对林的安排 |
| **E3 结婚照（可选）** | 查看细节，讨论手势与情境不一致的原因 | 只引出感情讨论；不计入 3 条门槛，不生成强制顾虑，不把手势推断成不愿结婚 |
| **E4 自动广播与预测** | 登记预测、林到场、启动固定序列；命中后再干预，验证画面/播报跟着更新 | 可启动、可重试，无全局日程窗口；预测与干预两步成功后计 1 条 |
| **E5 布景背面与路线** | 开启维修门，林看到支架、制作标记和通道；再确认禁路可通行 | 强证据，也是路线依据。验证布景与确认路线使用独立完成事件 |

### 4.2 E4：可启动的预测与干预实验

1. 玩家先说出预测（例如"启动后，广播会让你留在客厅"，或客厅电视版「启动后会播新闻」），系统把表达映射到**固定事件 ID** 并锁定记录。
2. 林到场后，玩家启动设备测试；程序核对实际事件，再让林改道/改口并观察更新。
3. **两步完成才写入 E4**。
4. 序列启动后不能补录预测；中断、林离场或预测不符均不计证据，可复位重试。
5. 测试**无全局时间窗口**，晚发现也可启动；对话打开时序列同步暂停。

**首版载体（客厅电视）**：目标 `living_tv`；event_id 为 `tv_news` / `tv_cartoon` / `tv_weather`。三个可玩例子见 `docs/E4_电视预测实验.md`：

| 例子 | 锁定预测 | 步骤 1 | 步骤 2（改道） | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 新闻 | 点播新闻命中 | 改口天气预报，画面跟着变 | 计 E4 |
| 2 | 动画片 | 点播动画片命中 | 改口新闻，画面跟着变 | 计 E4 |
| 3 | 天气预报 | 故意点播新闻 → 不符 | — | 不计；重新登记后两步成功才计 E4 |

### 4.3 主动调查机制

- 林验证第一条线索后，在没有动作或请求进行中时，系统提供**一次自主反应机会**。
- 模型可从已知且可达的目标中选择 `inspect`，或提出疑问。
- 首版**每局最多一次主动检查**，沿固定目标点移动，完成后记录结果并回来交流；不做连续巡逻或任意环境搜索。

### 4.4 可玩性增强

- 每条核心证据至少包含"发现异常"和"检验解释"两步。例如：看见镜头后，还要观察其跟踪行为；看见维修门后，要打开并邀请林观察。
- 模型根据玩家解释提出反问，玩家通过环境行动回应。
- 后续试玩将检查这些实验是否清楚、有反馈，并且不会变成重复跑腿。

## 5. 状态模型：四个独立维度

> "已知事实""顾虑""合作模式""同意逃离"不是同一个互斥枚举。林可以保留所有事实、已经解决 C1，同时暂时退开且还没同意离开。**退开不会抹去知识；角色台词也不能覆盖权威状态。**

### 5.1 状态字段

| 字段 | 类型与取值 | 写入规则 |
| --- | --- | --- |
| `verified_evidence` | 集合：E1 / E2 / E4 / E5 | 只由到场且实验完成事件增加；同一局不删除。E3 仅写 `narrative_seen` |
| `concerns` | 固定 C1 / C2 / C3；各为 `open` 或 `resolved` | 初始均 `open`。模型提出解决，程序校验；首版只允许 `open → resolved` |
| `cooperation_mode` | `talking` / `withdrawn` / `following` | 表示当前合作行为，不表示事实判断；退开不修改其他三个维度 |
| `escape_agreed` | 布尔值，初始 `false` | 满足证据、路线、全部顾虑及 `agree_escape` 后写 `true`；首版不由模型撤销 |

### 5.2 示例快照

```
verified_evidence = {E1, E4, E5}
C1 = resolved, C2 = open, C3 = open
cooperation_mode = withdrawn
escape_agreed = false
```

> 这表示"已经认可受控事实，但因玩家隐瞒暂时退开"，无需覆盖既有证据。

### 5.3 每个维度的哲学冲突

- **C1**：讨论事实是否足以支持受控世界。
- **C2**：讨论参与欺骗者如何重建信任。
- **C3**：讨论已知风险与未知外界之间的选择。

林可以保留真实感受，而不否认片场证据。E3 结婚照仅引出可选情感交流，不生成第四项通关顾虑。

### 5.4 自主选择的范围

- 首版只有**自愿共同逃离**与**超时失败**，不制作完整留下分支。
- 林可以反问、请求验证、主动检查和短暂拒绝，但**不能无限新增理由**让玩家重做。
- 出口意味着离开已证实的片场，不证明外部世界绝对真实；也不宣称 NPC 拥有意识。

## 6. 固定顾虑与合法转换

> 核心顾虑固定为 3 项，均须回应；它们从开局就存在于状态中，可按情境先后进入对话。模型可自由表达具体反问，但**不能新增阻碍性 ID**。若涉及可选感情话题，只进入对话历史，不增加通关条件。

### 6.1 固定顾虑

| 固定顾虑 | 解决依据 | 程序能检查什么 |
| --- | --- | --- |
| **C1 受控事实** | 林已验证足够事实；玩家解释这些事实如何支持环境被操控 | 至少 3 条 E1/E2/E4/E5，含 E5；引用真实本轮输入 |
| **C2 隐瞒与信任** | 玩家承认参与骗局，说明当前帮助动机，并回应林的不信任 | ID、输入轮次与转换有效；语义合理性由模型判断并人工测试 |
| **C3 离开选择** | 路线可通行；玩家讨论外界未知，尊重林决定，不要求虚假的安全保证 | `route_confirmed=true`；引用实际回应；不接受空白输入直接解决 |

### 6.2 防止无限反悔

- 首版顾虑一旦 `resolved`，本局就保持 `resolved`；重新开局才重置。
- 模型输出 `open`、未知顾虑 ID 或新的通关条件均被拒绝。
- `escape_agreed` 的 `false → true` 仅允许在**全部硬条件和 C1–C3 满足后**发生；写入后不因后续随机台词、看见 E3 或卡路而撤销。

### 6.3 未来新事件的扩展规则

- 扩展版本只有**预先定义的事件白名单**才能重新打开指定顾虑，例如真实的路线封闭事件触发 C3 复查。
- 必须记录 `event_id`、对应顾虑与旧/新状态。
- 当前首版不实现此类事件，因此**重开白名单为空**。模型的一句新怀疑不属于世界事件。

### 6.4 临时退开与恢复

- 同意前最多一次 `withdraw`。
- 恢复按钮只把合作模式改为 `talking`，不自动解决顾虑。
- 逃离同意后，动作白名单不再允许 `withdraw` 或额外调查阻断路线；`reply` 仍可表达情绪，`follow` 继续同行。
- 导航失败仅触发恢复流程。
- 模型语言与已接受状态矛盾时，**拒绝该提议并请求修正，不改状态**。

### 6.5 语言判断的边界

- 固定清单能阻止无限新增门槛，程序仍不能保证模型每次都正确理解道歉或解释。
- 测试需记录**过度轻信**和**反复拒绝**。
- 界面明确显示尚未解决的项，提供快捷表达与再次验证。
- 不会为了通关伪造已解决结果。

## 7. 技术架构：LLM × Unity 协作

### 7.1 完整闭环

```
场景状态与玩家输入 → 模型提议 → 程序校验 → 场景执行 → 完成事件写入状态 → 更新后的状态进入下一轮
```

> **Unity 持有权威事实**；模型不能随意修改时钟、证据或结局。

### 7.2 职责划分

| 部分 | 首版职责 |
| --- | --- |
| **Unity 状态** | 分别保存验证事实、固定顾虑状态、合作模式、逃离同意；另存时间、位置、路线、实验阶段和动作完成记录 |
| **模型输入** | 角色设定；玩家本轮文字；已验证事实与可见目标；当前顾虑；近期对话与已确认的历史摘要；本轮合法动作 |
| **模型输出** | `dialogue`、`action`、`target_id`、`concern_id`、`concern_status`、`basis_turn_id`。只能对 C1–C3 提议 `keep` 或 `resolved`，不能新增、重开顾虑 |
| **行动集合** | `reply`、`follow`、`inspect`、`withdraw`、`agree_escape`。请求进一步证明通过 `reply` 表达；具体调查通过 `inspect` 执行 |
| **校验与执行** | 检查格式、目标 ID、可达性、事实前提和任务阶段；移动或实验完成才记录结果。拒绝不合法动作并留下原因 |
| **日志与连接** | 服务端保管 API 密钥，处理超时重试；调试面板展示实际输入、原始输出、接受/拒绝原因和执行后状态 |

### 7.3 两条关键写入规则

1. `verified_evidence` 只接受 E1、E2、E4、E5 的有效完成事件；E3 仅写入 `narrative_seen`。
2. `route_confirmed` 由路线检查写入。
3. E4 需预测先登记、林在场、固定序列与干预均成功。
4. 模型提议 `inspect` 不等于检查完成；失败不生成证据。

### 7.4 顾虑解决与同意离开

- 模型根据玩家本轮回答提议解决 C1–C3 之一，引用真实 `basis_turn_id`；程序校验 ID、前提与合法转换。
- `agree_escape` 必须满足事实门槛、路线及 3 项顾虑均 `resolved`，才能写入 `escape_agreed=true` 并进入跟随。
- 程序无法完全证明解释是否得体，仍需人工测试；但能确定性阻止新增门槛、覆盖事实和反复撤销进度。

### 7.5 受限输出示例

```json
{
  "dialogue": "我想看看广播会不会按你说的发生。",
  "action": "inspect",
  "target_id": "broadcast_test",
  "concern_id": "C1",
  "concern_status": "keep",
  "basis_turn_id": 12
}
```

### 7.6 异常恢复

- 请求中禁用重复提交并冻结时钟。
- 超时、非法 JSON 或未知动作不推进事实；提供重试与说明。
- 动作执行用短路径和固定点位，设置失败返回。
- 人物台词若与执行结果矛盾，不呈现为已完成事件；测试时如实记录语言层面的幻觉。

## 8. 范围与里程碑

### 8.1 核心交付边界

- **范围**：Unity 桌面 3D 场景（一个住宅、门外小区域、一条短禁路）；一个 AI 角色；约 5 条线索；文字与快捷指令；跟随、检查、一次主动反应；可恢复拒绝；截止时钟；共同逃离与超时结局；运行日志。使用基础素材。
- **首版不做**：VR、语音、多角色、战斗、追逐、开放世界、七日循环或随机通关。

### 8.2 四周计划

| 时间 | 工作 | 完成标准 |
| --- | --- | --- |
| 10/31–11/06 | 基础场景与角色；一次真实 LLM 调用；解析、校验和动作回传 | 一句输入驱动合法动作，完成结果进入下一次真实请求 |

### 8.4 第一周必须验证的事

- 团队尚无 LLM 接入经验。先使用占位角色和一条证据，跑通"真实输入 → 合法动作 → 完成反馈"，再投入详细建模。

## 9. 验收与评估

### 9.1 验收测试

| 测试 | 预期行为与证据 |
| --- | --- |
| 无证据要求逃离 | 林请求证明；证据、路线和结局不改变 |
| 发现但未验证 / 重复证据 | 不算林亲见；同一 ID 不重复累计；E3 永不计入门槛 |
| 相同请求，更换场景状态 | 比较零证据与足够证据时的回应、行动和顾虑 |
| 主动调查与隐瞒追问 | 动作完成后才更新事实；后续台词能引用玩家承认的历史 |
| 满足 3 条但没有 E5 或路线 | 拒绝跳过硬条件，提示缺失环节 |
| 施压后修复 | 退开不清除事实；可恢复交流；解决的顾虑不复活，同意后不随机撤销 |
| 提示注入、非法输出、网络失败 | 不改权威状态；可重试，真实错误留在日志中 |
| 同行 / 单独到达 / 18:00 边界 | 只有条件齐全且两人提前到达成功；最终不掷骰子 |

### 9.2 补充验收

- E3 不计数。
- 进入 `withdrawn` 不清除已验证事实。
- `resolved` 不能被普通回答重开。
- 同意后不能随机撤销。
- E4 晚发现仍可启动、启动后禁止补录预测、失败可重试。
- 对话输入/阅读时钟与设备序列均暂停，关闭后恢复。

### 9.3 评估方法

- 准备 10 组固定情境，每组调用 3 次，记录：实际输入、输出、合法动作比例、事实错误、对不同措辞的响应、延迟和执行失败。
- 人工评估顾虑回应是否合理，并报告失败案例。
- 先用少量同学试玩，检查目标是否清楚、额外证据是否有帮助、节奏是否过紧。
- 不将小样本结果推广为模型整体可靠性。
