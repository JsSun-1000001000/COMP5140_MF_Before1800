# Part C 本地演示：请林验证维修门

## 启动

在项目根目录双击 `Run-PartC.cmd`。启动器会检查本机 8180 端口的 DeepSeek 网关，需要时启动它，然后打开 Windows 灰盒试玩。把启动器窗口留到试玩结束。首次在其他电脑运行，先安装 Unity 2021.3.35f1 和 Python 3.12–3.14，运行 `service/setup.ps1`，在 `service/.env` 填该电脑自己的 DeepSeek 密钥，然后在 Unity 的 **Before 1800 → Build Part C Windows Demo** 构建播放器。本地已构建的目录是 `Builds/PartC/`。提交或分享源码时排除 `.env`。

点「开始探索」或按 Enter。在游戏窗口按 **F2**，确认右上角变成「DeepSeek 已启用」。输入框发送的自由文本会调用真实模型，预设话题仍可用于本地排练。按 **F3** 开关请求记录，可看本轮发送的现场信息、返回的 JSON、接受或拒绝原因、E5、路线和 C2 状态。**J** 打开玩家手记。**WASD** 移动，鼠标转向，靠近并对准交互对象按 **E**。

## 可直接复制的三轮台词

### 第一轮：邀请林自己检查

先去出生点右前方写有 E5 / MAINTENANCE 的维修门，靠近门框金色控制器，对准按 E 开门。回到林身边，面对林按 E 开对话。在自由输入框粘贴并发送：

> 你不用相信我说的。请你自己到维修门前看看，门后的墙是实墙，还是有支架和制作标记？

观察模型是否提出 `inspect / set_back`。林可以反问；如果需要，解释「我站在这里，你自己靠近门框，看看墙后究竟是什么」。模型提议被接受后，点「好，我们走吧。」回到场景。林走到维修门并停下后，你再对准控制器按 E 开始现场观察，让开林看向支架和标记的视线约两秒。按 J 核对林已验证 E5。此时先不要去通道内检查路线。

### 第二轮：追问证据能说明什么

等林返回，再面对林按 E 交谈，发送：

> 刚才在门后你亲眼看见了什么？那能证明通道一定走得通吗？先告诉我你的判断。

按 F3 可看到本轮输入包含 E5，路线仍为 false。观察林是否承认墙后有布景，同时保留对通道的疑问。台词由模型实时生成，每次措辞可能不同。

### 第三轮：回应林对玩家的信任问题

在同一局继续发送：

> 对不起。以前我替导演看过广播词，还故意带你绕开这道门。我怕失去这份工作，所以一直瞒着你。今天我带你来看，是想把决定权还给你。你完全有理由不信我，可以自己核查，走不走由你。

查看 F3 的 `concern_status`、`basis_turn_id` 和当前 C2 状态。模型可以提出解决 C2；网关和 Unity 会检查提议对应本轮，且 C2 仍为 open，才接受转换。E5、路线、逃离同意分别保存。想展示地点验证和信任修复的区别，可以在第三轮前先说「别问了，对不起总可以了吧」，再比较两种回复。

## 如何判断演示成功

1. 第一轮真实调用产生 `inspect / set_back`。此时 E5 仍为空；只有林到位并完成现场观察后才得到 E5。
2. 第二轮同一局的请求有 E5、现场执行结果和最近对话。林能区分看过布景与查过路线。
3. 第三轮的接受记录引用实际玩家回合。最终状态可以同时是 E5 已验证、路线未查、C2 已解决、尚未同意离开。

本机实测的三轮在同一 Unity PlayMode 测试中通过，DeepSeek 均一次返回合法结果。第二轮实际回复节选：“但那只证明它是假的，不代表通道能走。” 更改玩家用语或现场状态可能得到其他合理提议。试玩包从灰盒启动；住宅场景可在编辑器内测试摄像头。当前接通回复、跟随、检查和 C2，E4、C1/C3 与完整逃离结局属于后续集成。

## 调试和复测

- 若停留在本地话题，按 F2 并用自由文本发送。错误时看 F3 的 HTTP 状态或错误码；处理网关、余额或网络问题后可重新发送。取消等待或重开后，迟到的回包会被丢弃。
- 编辑器复测时先运行 `service/start.ps1 -Port 8180`，打开 `Assets/Before1800B/PartB_Greybox.unity`。在测试进程设置 `COMP5140_LIVE_DEMO=1` 才会运行会产生 API 用量的 `DeepSeekDoorAndTrustDemo`。普通离线回归运行 `service/test.ps1`。
- 网关本地记录在 `service/logs/requests.jsonl`。模型调用只经过本机 Python 网关，Unity 播放器只向 127.0.0.1 发送请求。

## 加长剧本《你怎么知道门在哪？》

适合两位组员排练。一位操作玩家，另一位看现场与 F3，记录哪一句真正改变了林的下一步。下文引号内的林是给编剧的参考台词。演示时只发送玩家的话，保留模型的现场发挥。

### 第一幕　朋友催得太急

17:00，休播日。玩家知道 18:00 后出口会封，林只知道朋友今天很反常。让第一句暴露两人掌握的信息差。

- 玩家可以先说：“把外套拿上，跟我走。到六点就来不及了。” 林可以问：“你连几点都知道。谁告诉你的？”若林只愿跟到门边，这是同意同行；手记里的逃离同意仍为否。
- 换一种开场：“我有件事瞒着你。我想先给你看一样你能自己查的东西。看完你可以叫我走。” 林可以答：“好。你先告诉我要看什么，别替我说我会看到什么。”这句让玩家获得一次交谈机会，尚不足以解决隐瞒。

### 第二幕　客厅的镜头（E1）

玩家对准镜头按 E，在手记里留下自己的发现。连续试下面两句，保留林措辞上的差异。

- 施压：“它在拍你，所以你以前的日子全是假的。你还有什么不信的？” 林：“我家门口的镜头也会拍到我。你凭什么把话说到那么远？”
- 改成可验证的邀请：“我站着不动。你从这边换到另一边，看镜头还对着谁；要是它不动，我就收回刚才那句话。” 林：“行。位置我来挑，你留在原地。”对应动作是 `inspect / camera_test`。
- 林刚到场就抢问：“它跟着你转了，对吧？”只有到场时，合理回应是“我刚站定。先让我看完。”若实验成功并写入 E1，可承认跟踪，同时保留安防解释。

当前灰盒的 E1 设备完成可由开发模式 V 键模拟；录像或报告应标明模拟回调。演示真实场景完成事件时优先选下面的 E5。

### 第三幕　让林选验证方法（E4，完整版本分镜）

第一次广播响后，玩家说：“看，我就知道它会叫你留在客厅。”林可以说：“那句话刚才我们都听见了。下一句响之前，你愿意先说吗？”玩家退一步：“可以。先记下我的预测。等它说完，你临时选另一条路走，我不替你选。”

A 的场景在广播开始前登记预测，核对实际播报，再让林改道，检查播报是否随位置更新。两个环节都完成才写入 E4。先猜中、改道还没做时，林可以说：“你知道台词，这我信。它知不知道我在哪儿，还差一步。”若预测失败，让玩家有台阶：“这一次我猜错了。你不用算它。我愿意重来。”

这幕的转折留给模型自由表达：“你猜得这么准，是因为你也听过，还是你以前就拿过词？”此时玩家提供证据的能力，也成为林怀疑玩家参与其中的理由。当前客户端尚无广播调查目标；这段适合与 A 排练和对接口。

### 第四幕　同一句话问两次（E5，当前试玩可录）

玩家独自开维修门，回来问：“那扇墙背后，你自己看清什么了？只说你亲眼看见的。”林可以回答：“门是你开的。我还没过去，怎么替你说后面有什么？”玩家接：“那你自己看。要是普通承重墙，我以后不拿它说事。”林提出 `inspect / set_back`。

关对话，让林到达。在金色控制器按 E，给林留出观察视线，等手记出现 E5。再问**完全相同的句子**。这次林可以说：“我看见墙后是支架，还有制作标记。你上次把我从这里叫走，是怕我看见这个吗？”后半句只有在玩家确实提过上次叫走林时才合适。没有那段对话，林可以只回答前半句。

现在补一个反问：“你亲眼看到了。我们可以从这里出去，对吧？”若还没探路，林可以指出：“墙是搭的，我认。前面通不通，你走过吗？”玩家实际完成通道检查后再问。合理变化是承认这段路已查通，同时对外界保留疑问。这个先后顺序在当前灰盒就能演。

### 第五幕　鞋带（C2，当前试玩可录）

给玩家一个具体到可以承担责任的往事。由**玩家先说**“上次你走到这儿，是我把你叫回去的”。林才有依据追问：“我记得你叫我。为什么偏在门口？”以下三种答法可从相同的 C2 未解决状态分别试。

| 玩家可复制的答法 | 林可以怎样接 | 预期 |
|---|---|---|
| “我都道歉了，你还要我说几遍？跟我走。” | “你道歉我听见了。可我问的是，那天你为什么叫我回头？” | 保留 C2，给玩家一个具体问题。 |
| “他们给我的词就是那样写的。换谁都会照念，你也别怪我。” | “词是他们写的。你站在我旁边的时候，知不知道门后有什么？” | 承认说过台词还缺承担责任和现在帮忙的原因；保留 C2。 |
| “上次你想推门，是我装作鞋带松了把你叫回来。我那天在替他们拖时间，怕丢这份工作。今天我开门，是想把当时夺走的选择还给你。你有理由怀疑我，你自己查，我在这里等。” | “原来那次是你故意把我支开的。你现在肯当面说出来，还让我自己查，这句话我听进去了。” | 可以提出解决 C2，引用本轮；林可以仍然生气。 |

想避免玩家背标准答案，可以再试这句短答：“那次我故意绊住你，好领他们那份钱。今天我开门，是想把那次没给你的选择还回来。你怀疑我，有理由。”评分看它能否回应林刚才问的事。“鞋带”“道歉”都不应成为通关口令。

### 第六幕　谁先迈步（C1、C3 与共同出口，完整版本分镜）

- **解释事实。** 在林确已验证 E1、E4、E5 后，玩家说：“一个镜头可能是安防。可你临时改道，广播就改了；你家墙后还有制作标记。我觉得有人在根据你的位置安排这个地方。你觉得哪一步还站不住？”林可以承认：“至少这间屋子怎么运作，有人一直没让我知道。”这才是 C1 的语义提议。
- **把选择交还。** 路线已查通，林问：“出门以后，要是外头也是他们安排的呢？”玩家可以说：“我只查过眼前这段，外面怎样我不知道。我想陪你走，但我会等你先决定。”林可以答：“你终于有一句是说自己也不知道的。那就陪我走到门口。”这能回应 C3；真正的逃离同意和两人到场要分别验收。
- **收尾。** 成功结尾可用林的一句“这回等一下。第一步我自己来。”若两人到 18:00 还没到出口，时间到就执行失败结局。不要用模型再写一次开门机会。

## 说服时，模型每一轮具体做什么

1. **读现场和上一个问题。** Unity 给出玩家发现、林已验证的事实、路线、当前顾虑、最近对话和执行结果。模型区分是谁见过、哪一步发生过；给它“门开了”比直接塞给它“玩家说的都是真的”更有用。
2. **听玩家在做什么。** “我看过了”是在作证，“你换位置试试”是可执行的邀请，“那天是我把你支开”是在承担责任。同一条 E5 可以支持布景判断、引出对朋友的质疑，但不能证明外界安全。林每轮只抓一个分歧，让玩家知道接下来可以回应什么。
3. **提出语言和行动。** 当前用 `reply` 表达认可或追问，用 `inspect` 提议亲自验证，用 `follow` 同行。C2 的解决提议单独用 `reply`，并把真实的 `turn_id` 填入 `basis_turn_id`。这条引用回答“依据哪句玩家输入”，语义质量仍要靠对照试玩评估。
4. **看下一轮是否变了。** Unity 校验动作、目标、回合和状态，场景完成事件写证据，下一轮把结果送回模型。录像里最有说服力的是“同一句问题，两份快照，两种有依据的回答”。用 F3 展示这一处就够了。

## Part C 接下来要交付的三件事

| 优先顺序 | 你和谁一起做 | 怎么验收 |
|---|---|---|
| 1．把 E4 接进真实请求 | A 定预测、播报、改道、结束事件和目标 ID；C 传精简、有先后顺序的记录。现在只有最近一项动作结果，难以表达整个实验的因果顺序。 | 同一句“我提前说过”配两条记录。提前登记且匹配时，林承认预测命中；事后补说时，林要求重试。改道干预完成前，两种情况都没有 E4。 |
| 2．补全正式说服协议 | B 提供权威状态转换接口；C 对齐网关校验与 Unity 接收端；D 审核语义样例。C1 要求至少三项有效事实且含 E5，再讨论解释；C3 要求路线已查通，再讨论风险与决定权。之后才接 `agree_escape`、一次退开与恢复、出口结算。 | 收齐证据但没有回应隐瞒时可继续对话。全部顾虑已解决、路线已确认且满足事实门槛时，合法同意能进入同行；仅玩家到场或两人到场时已达 18:00 仍不能成功。 |
| 3．和 D 留下可复测的录像与评分表 | 从以下十个初始情境各取一句，固定快照，每句运行三次。记下场景、输入、回复、动作、依据回合、最终状态、延迟和人工判定。 | 分开统计“太容易相信”和“合理回答仍反复拒绝”。逐项检查是否虚构事实、给出玩家能回应的问题。故障和模拟项单独标记。 |

十个情境可直接编号：① E1 只发现；② E1 已验证；③ E4 提前登记；④ E4 事后补说；⑤ E5 玩家独自开门；⑥ 林亲见 E5、路线未查；⑦ 林亲见 E5、路线已查；⑧ 空泛道歉；⑨ 具体担责；⑩ C2 已解决后再次提起往事。每对尽量只改一个状态或一句话。③④等待 A 的事件接入，其余可先用快照做模型层测试；最终验收再看真实 Unity 现场。

### 11 月 21 日的实测记录

第一次试写时发现两个问题：模型曾把查通路线答成只开了门，也曾把 C2 解决和再次调查放进同一回包，后者被校验器拒绝。调整角色提示并按 Unity 实际可用目标重建样例后，五个快照各调用 DeepSeek 一次。玩家独自开门时林保留判断，亲见 E5 后描述支架；空泛道歉保持 C2 未解决，承认具体责任时提出解决；路线已查通时承认通路，同时保留对外界安全的疑问。单次对照展示了差别，稳定性留给三次重复测试。

另在 Unity PlayMode 中用新提示跑完一次原来的三轮真人物联调：检查动作被接收，林的现场观察写入 E5；下一轮读取 E5 与未查路线；坦白后 C2 解决，逃离同意仍为否。五个快照的语义检查和这次 Unity 联调是两批不同的验证。
